How order detection works

Dhan's Live Order Update WebSocket documentation provides the master order stream. Orders are routed to each enabled child using that account's broker integration. Angel One children require an unambiguous matching futures contract by underlying and expiry. Supported pending-order changes and cancellations are sent through the child broker's API. Bracket/cover, after-market, disclosed-quantity, unsupported product/validity, and ambiguous/missing contract mappings are rejected rather than silently altered.

Copying only runs while this API is online and connected. Each observed master order is recorded once; child orders use a stable correlation ID for tracking. Dhan documents correlation IDs for tracking, not as an exactly-once guarantee; a network failure at submission time can still be ambiguous. Copying does not guarantee matching execution prices, fills, available funds, or that either broker will accept every child order.
